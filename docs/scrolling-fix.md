# 滚动回弹修复记录（2026-10-31）

修复的是自定义动画与 WPF 虚拟化坐标修正之间的冲突。没有关闭虚拟化，没有增加缓存页数，也没有添加布局后的锚点补偿。

## 原因与证据

`VirtualizingStackPanel` 在测到新的块高度后，会调整内容总高度与绝对滚动偏移。WPF 本身会对小范围滚动建立锚定；因此“系统完全没有锚定”不是准确描述。相关实现在 [WPF 的 SetVerticalOffsetImpl](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Controls/VirtualizingStackPanel.cs)。

旧动画保存固定的绝对目标。一旦布局重定位把当前偏移移到目标另一侧，下一帧就会反向追旧目标。旧版本逐帧回放实际复现了视口内反跳：最大 40 像素；例如第 45 帧偏移为 13218，旧目标为 13251.42，虽然滚轮向上，动画仍把偏移往大处拉。

原始报告：`artifacts/scroll-old-replay3/verification.json`。回放先处理 WPF 的布局队列，检查文档确实移动，再比较同一个数据块的屏幕位置；不会把回收后复用的容器当作原来的块。

## 实现

- 保存带方向的剩余滚动距离，而不是固定绝对目标。
- 每帧从当前偏移前进一小段，并扣除已请求的距离。布局坐标修正不会改变剩余距离或动画方向。
- 方向反转仍清除旧方向余量及已排队命令；鼠标点击、滚动键、锚点/脚注导航会停止旧动画。
- 保留原来的速度、指数衰减、代码块滚轮路由、Shift 横向滚动和系统关闭动画分支。

## 验证

`artifacts/scroll-final/verification.json` 是修复后的完整报告。

六种逐帧回放覆盖向上、向下、高频小增量上下滚动、交替方向，以及屏幕上方缓存块延迟增高。共检查 2160 帧，视口内最大反跳为 **0 像素**。缓存区局部重排不等于可见回弹，报告分别记录两者。每组也记录实际画面滚动距离，防止“不动就通过”。

高频输入使用非 120 整步的增量和变化的帧间隔。这些是明确构造的回放序列，并非用户真实鼠标或触控板的采集记录；不能据此声称覆盖所有硬件时序。

完整功能验证通过。20 MiB、115200 块文档仍仅实现页首 9 / 页尾 10 个容器，本轮测试进程保留托管内存约 130.6 MiB。解析和离屏布局约 2.42 秒；该数据不是冷启动基准，也不用于宣称性能提升。

关键文件：`src/MokiPad/Controls/MarkdownPreview.cs`、`tests/MokiPad.Verification/ScrollReplay.cs`、`tests/MokiPad.Verification/Program.cs`。

## 同方向突跳的后续修复

用户确认反跳消失后，继续反馈“滚动中偶尔突然多跳一段”。原先只检查方向与最终距离，不能排除一帧走得过远。

新增测试使用屏幕外的原生 HwndSource，运行真实的 WPF 渲染与布局队列，保留窗口相同的布局取整设置。覆盖混合高度文档和代码清理文档，分别运行普通滚轮、连续突发滚轮、期间阻塞 UI 线程 110ms 的突发滚轮。它们仍是构造的输入，不是用户设备采集记录。

停顿前的版本会用最长 50ms 的时间差推进指数动画，停顿后一次追赶过多。在相同原生测试视口中复现最大单帧位移 82px；累计距离本身没有重复。

修复后：

- 每次呈现帧最多消费一次滚动距离，避免布局触发相同帧的重复 Rendering 回调。
- 单次计算只推进最多 1/60 秒，停顿的时间不会在下一帧一次性追赶。
- 单帧请求位移限制为视口高度的 12%，下限 48px、上限 96px；剩余距离继续平滑消费。
- 累计不足一个设备像素的位移，避免更多小步被布局取整吞掉。

专项复测中，最大单帧位移降至 48px，累计输入与实际移动均为 2625px，反跳仍为 0。动画自然结束后再检查总距离，测试没有靠强制跳到最终位置来通过。
